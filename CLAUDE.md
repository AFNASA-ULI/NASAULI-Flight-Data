# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

A public **data repository** for flight telemetry from a Tarot 450 quadcopter (NASA ULI data collection),
plus a small Python pipeline (`nasauli/`) that turns the raw logs into cleaned data, per-flight HTML reports,
and a GitHub Pages site. See README.md for the user-facing description.

Logs are offloaded from an onboard Raspberry Pi that runs the logger and streams telemetry over MAVLink from
the flight controller. Wind data comes from a separate "wind drone" that records a ROS 2 bag.

## Layout

```
<flight folder>/raw_data/     original files, never edited (flight CSV, wind_drone_* bag + *_csv export)
<flight folder>/processed/    generated by `python -m nasauli process`; never edit by hand
nasauli/readers/              one module per raw format -> standard schema (nasauli/schema.py)
nasauli/clean.py              local position, wind trimming (on GPS-corrected time)
nasauli/checks.py             summary numbers + data-quality findings
nasauli/report.py, site.py    HTML report per session, index page
.github/workflows/flight-data.yml   on push to main: process, commit processed/, deploy Pages
```

Flight folders are named `Tarot450_<UTC timestamp>` (offload time); the CSV name inside holds the session start
time. Older folders may hold files in formats that have no reader (e.g. `Tarot450_20260408/`, "v1"); the
pipeline skips those and the site lists them as raw-only.

## Commands

```bash
pip install -r requirements.txt
python -m nasauli process [FLIGHT_DIR ...]   # all flights by default
python -m nasauli site --out _site
```

There is no test suite; validate a change by running `process` on all flights and checking the output
(row counts, metadata checks, and the HTML report).

## Conventions

- Never modify files under `raw_data/`. Corrections belong in the reader or the cleaning step.
- New logger format: add `nasauli/readers/<name>.py` (`NAME`, `sniff`, `read`) and register it in
  `readers/__init__.py`; keep the old readers. The v2 reader looks columns up by name, so added or removed
  columns within v2 need no reader change.
- Anything that changes processed outputs: bump `nasauli.__version__`.
- v2 raw logs start with `# key: value` lines ending in `# ---`. Column groups map to MAVLink messages
  (`HB_`, `ATT_`, `IMU_`, `GPS_`/`POS_`, `BAT_`, `VFR_`, `SRV*_us`, `VIB_`, `EKF_`, `BARO_`, `WND_`, ...), with
  `*_rx_UTC`/`*_Age_ms` giving receive time and staleness.
- Known logger quirks handled by the pipeline: `HB_Armed` mixes heartbeats from several components (the
  autopilot's have base_mode bit 0 set); the `IMU_*mag_mT` columns hold milligauss; the host clock is not
  chrony-synced (offset estimated from `SYST_UnixUsec`).
