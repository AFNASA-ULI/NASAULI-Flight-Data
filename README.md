# NASA ULI Flight Data

Flight telemetry from the NASA University Leadership Initiative data collection (Tarot 450 quadcopter),
plus wind-sensor data recorded alongside the flights.

**Browse the flights:** https://afnasa-uli.github.io/NASAULI-Flight-Data/ (interactive report per flight,
data-quality notes, and downloads of the cleaned data).

## Layout

```
<flight folder>/
  raw_data/                    logs exactly as offloaded; never edited
    TAROT_450_<start>.csv        flight log (nasauli session log v2)
    wind_drone_<...>/            ROS 2 bag from the wind drone (.mcap + metadata.yaml)
    wind_drone_<...>_csv/        the same bag exported to CSV (used by the pipeline)
  processed/                   generated by the pipeline; don't edit by hand
    <session>.parquet / .csv     cleaned flight data, standard schema
    <session>_wind.parquet/.csv  wind data trimmed to this flight's time window
    <session>_metadata.json      header, summary, data-quality checks, column units, provenance
    <session>.html               interactive report
nasauli/                       the processing pipeline (Python package)
notebooks/explore_flight.ipynb load and plot a processed flight
```

## Adding a new flight

1. Create a folder (e.g. `Tarot450_<YYYYMMDD_HHMMSS>Z/raw_data/`) and put the flight CSV and the wind-drone
   bag + its `_csv` export in it.
2. Push to `main`. The GitHub Action processes every flight, commits the updated `processed/` files, and
   republishes the website. Nothing to run locally.

To run it yourself:

```bash
pip install -r requirements.txt
python -m nasauli process                      # all flights (or: python -m nasauli process <folder>)
python -m nasauli site --out _site             # build the website locally; open _site/index.html
```

## Cleaned data

`processed/<session>.parquet` (or `.csv`) holds one row per logger sample. Its first columns are a
**standard schema** with fixed names and SI-style units (`time_utc`, `time_gps_utc`, `alt_rel_m`, `roll_deg`,
`batt_voltage_v`, `north_m`, …; full list with units in `nasauli/schema.py` and in every metadata JSON).
The remaining raw logger columns follow under their original names, so nothing is dropped.

```python
import pandas as pd
df = pd.read_parquet("Tarot450_20260925_165053Z/processed/TAROT_450_20260923T153559Z.parquet")
```

Notes:

- `armed` uses only the autopilot's heartbeats. The raw `HB_Armed` column also contains heartbeats from other
  MAVLink components (e.g. the ground station), so it flips on and off.
- `time_gps_utc` is the logger's clock shifted onto the autopilot's GPS time (the logger clock was not
  synchronised; the offset is in the metadata). Wind data is matched on this clock.
- Wind data: `vector.x` of the wind sensor's message is treated as speed (m/s) and `vector.y` as direction (deg).

## Log format versions

Each raw log declares its format on its first line (`# nasauli session log v2.0.0`). The pipeline picks a
**reader** for it (`nasauli/readers/`), and each reader converts its format into the standard schema. When the
logger format changes, add a new reader next to the old one; older flights keep processing unchanged. Every
output records the pipeline version and reader that produced it.

The April 2026 flight (`Tarot450_20260408/`) uses an older format without a reader, so it is published as raw
data only.
